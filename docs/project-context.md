# Project Context

Project Context is the durable understanding of why a repository exists and how it fits into the wider work graph.

It is derived primarily from repository documentation and guidelines.

It should answer: why the project exists; what problem it solves; users/consumers; its role; capabilities; dependencies/integrations; boundaries; runtime/deployment; engineering constraints; terminology; related projects/repos; documented facts versus inference; unknowns.

Primary sources are CLAUDE.md, README, docs, architecture/design docs, ADRs and contribution/development guides. Code, tests and configuration validate and enrich the documented model.

Project Context is used by project management, status, delegation, session preparation/spawning, related-topic search and cross-project correlation. Refresh incrementally when relevant documentation changes.
